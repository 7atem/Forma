# First usability study — ready-to-run protocol

Target: 10–15 consenting adult Arabic/English speakers using an existing resistance-training routine. This is a product usability study, not a clinical trial. No participants have been recruited or tested by this implementation.

Invite users through a channel the product owner has chosen. Do not contact anyone automatically. Explain that this is a development build; users can use fictional records. Do not request medical histories, progress photos or raw private logs for feedback.

## Tasks

1. Create a profile and weekly schedule without entering nutrition targets unless already chosen.
2. Save a program using familiar exercises and choose its order/timer.
3. Log two sets, finish the session and correct one entry.
4. Add a food from a label, state its reference amount/unit/source, and log a different portion.
5. Build a recipe from two saved ingredients and explain what one serving means.
6. Add yesterday's meal and measurement; find and correct them.
7. Read the weekly review and explain what a missing food day means.
8. Record changed availability in a check-in. Explain the pending proposal before confirming it.
9. Export an encrypted backup. Preview it, cancel, and verify the current log remains. Then restore a fictional backup on a test install.
10. Switch language / use large text, and report any clipped or confusing controls.

## Record with permission

Language and approximate screen-size category; task success without help; time to save a set; wrong-unit or wrong-date attempts; confusing source/portion concepts; understanding of incomplete data and AI limits; whether the weekly review is worth returning to. Collect observations and comments, not raw sensitive records. Use anonymous participant codes and an agreed deletion date.

## Decision meeting

Review the biggest sources of friction, repeated misunderstanding and data-loss risks. Fix those before adding more AI. Do not invent completion rates, retention or willingness-to-pay figures. Move to the 30–50-person beta only after the owner reviews actual observations and the release gates are met.
